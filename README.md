# Интернет‑магазин — учебный проект на Django

## Описание

Это учебный проект интернет‑магазина, разрабатываемый поэтапно в рамках курса.
На каждом занятии добавляются новые компоненты: от базовой настройки окружения до реализации бизнес‑логики.
К завершению курса проект будет представлять собой полноценный прототип для портфолио.

## Цели проекта

- Освоить разработку на Django с нуля.
- Отработать практику работы с Git (ветки, коммиты, слияния).
- Создать структурированный веб‑проект с разделением на приложения.
- Научиться интегрировать фронтенд‑решения (Bootstrap, HTML‑шаблоны).
- Сформировать портфолио‑проект с реальными функциями интернет‑магазина.

## Текущий статус

**Этап разработки:** Первоначальная реализация и построение основ системы.

**Реализовано:**

### Этап 1: Начальная настройка проекта и окружения

- Инициализирован проект Django.
- Настроена структура Git (ветки `main`, `develop`).
- Создано приложение `catalog`.
- Подготовлены шаблоны страниц (главная, контакты).
- Реализованы базовые контроллеры.

### Этап 2: Подключение и настройка базы данных

- Проект подключен к СУБД PostgreSQL.
- Созданы и настроены модели `Product` и `Category`:
    - Модель `Product`: наименование, описание, изображение, категория, цена, дата создания, дата последнего изменения.
    - Модель `Category`: наименование, описание.
- Применены миграции для переноса моделей в базу данных.

### Этап 3: Настройка административной панели и наполнение данными

- Создан и настроен суперпользователь.
- Зарегистрированы и настроены модели `Product` и `Category` в административной панели Django:
    - Для `Category`: отображение `id` и `name`.
    - Для `Product`: отображение `id`, `name`, `price`, `category`.
    - Настроена фильтрация продуктов по категории.
    - Настроен поиск по полям `name` и `description`.
- Через Django shell созданы категории и товары, выполнены запросы для получения списков категорий и товаров, фильтрации
  по категориям, обновления цен и удаления товаров.

### Этап 4: Вспомогательная инфраструктура и автоматизация

- Сформированы фикстуры для моделей `Category` и `Product`.
- Создана кастомная команда для добавления тестовых продуктов, предварительно очищающая таблицу перед добавлением новых
  данных.

### Этап 5: Шаблонизация и оптимизация интерфейса

- **Создание детализированной страницы товара**: разработан новый контроллер и шаблон для отображения всей информации о
  конкретном товаре.
- **Отображение списка товаров на главной странице**: внедрен цикл для вывода карточек товаров с ограничением описания
  до первых 100 символов.
- **Оптимизация структуры шаблонов**: выделен общий (базовый) шаблон с элементами шапки, подвала и стилей. Дополнительно
  создан подшаблон для главного меню, позволяющий избежать дублирования кода и облегчить дальнейшую поддержку проекта.

### Этап 6: Рефакторинг и расширение функционала для SEO-продвижения

- Разработка блога и интеграция в проект
    - Создано отдельное приложение для блога и добавлено в конфигурационный файл `settings.py`:
    - Разработана новая модель для постов блога

- Реализация полного набора операций CRUD для модели поста блога выполнена с использованием CBV:
    - ListView для просмотра списка постов
    - DetailView для просмотра отдельного поста
    - CreateView для создания нового поста
    - UpdateView для редактирования существующих постов
    - DeleteView для удаления постов

- Модификация логики обработки запросов
    - Внедрена логика увеличения счетчика просмотров при открытии отдельной статьи:
    - Реализована фильтрация опубликованных статей посредством переопределения метода `get_queryset()` в представлении
      `ListView`:
    - Организовано перенаправление пользователей на страницу просмотра статьи после её успешного редактирования:
- Дополнительное задание: отправка уведомления на электронную почту при достижении статьей отметки в 100 просмотров.

### Этап 7: Реализация CRUD‑операций и валидации для модели продуктов

**Реализация механизма CRUD для модели продуктов:**

- создан класс формы для продукта с использованием модуля `django.forms`;

- реализованы CRUD‑операции (создание, чтение, обновление, удаление) для продуктов через формы;

- собраны шаблоны с использованием форм;

- форма подключена в соответствующие контроллеры работы с продуктом;

- в форме отображены все поля для создания/обновления объекта продукта;

- собран шаблон для подтверждения удаления продукта.

**Валидация данных:**

- реализована валидация на запрещённые слова для полей «название» и «описание»:

    - список запрещённых слов (`казино`, `криптовалюта`, `крипта`, `биржа`, `дёшево`, `бесплатно`, `обман`, `полиция`,
      `радар`) хранится в константах и пере используется в методах;

    - проверка наличия запрещённых слов (в любом регистре) выполняется в методах `clean_...` для соответствующих полей
      формы;

- добавлена кастомная валидация для поля `price`:

    - реализован метод `clean_price` в форме, проверяющий, что цена не может быть отрицательной;

    - при некорректном вводе отображается сообщение об ошибке через `ValidationError`.

**Стилизация форм:**

- формы продукта стилизованы с использованием метода `__init__`;

- обеспечено соответствие общей стилистике платформы;

- булево поле (checkbox) стилизовано корректно и отображается как чекбокс, а не просто строкой.

**Дополнительное задание: загрузка и валидация изображений:**

- реализован механизм загрузки изображений продуктов;

- добавлена валидация для поля загрузки изображения:

    - проверяется формат файла (допускаются только JPEG и PNG);

    - проверяется размер файла (не более 5 МБ).

### Этап 8: Реализация системы пользователей и аутентификации

**Выполненные задачи:**

**Создание приложения для работы с пользователями:**

- создано новое приложение для управления пользователями в проекте Django;

    - разработана модель пользователя на базе `AbstractUser`, где электронная почта используется как поле для
      авторизации;

    - добавлены дополнительные поля в модель пользователя:

        - аватар (изображение);

        - номер телефона;

        - страна.

**Реализация функционала аутентификации:**

- **регистрация пользователя**:

    - создана форма для регистрации с полями электронной почты и пароля;

        - реализована логика регистрации в представлении, позволяющая пользователю создать учётную запись;

        - настроена отправка приветственного письма пользователю после успешной регистрации;

    - **авторизация пользователя**:

        - разработана форма и представление для авторизации по электронной почте и паролю.

**Настройка прав доступа:**

- закрыт доступ к страницам, связанным с управлением продуктами, для анонимных пользователей;

    - обеспечена возможность просмотра, создания, изменения и удаления продуктов только для авторизованных
      пользователей;

    - оставлена общедоступной только страница просмотра списка товаров.

**Дополнительное задание: интерфейс редактирования профиля пользователя:**

- разработан интерфейс для редактирования профиля пользователя;

- реализована возможность изменения дополнительных полей (аватар, номер телефона, страна) в личном кабинете
  пользователя.

### Этап 9: Реализация системы ролей и разграничения прав доступа для управления продуктами

**Выполненные задачи:**

**Работа с группой «Модератор продуктов»:**

- создана группа «Модератор продуктов»;

    - к модели `Product` добавлено кастомное право на отмену публикации продукта (`can_unpublish_product`);

    - для группы «Модератор продуктов» настроены следующие права:

        - право на отмену публикации продукта (`can_unpublish_product`);

        - право на удаление любого продукта;

    - реализована проверка наличия соответствующих прав у пользователя при попытке:

        - отменить публикацию продукта;

        - удалить продукт;

    - обеспечено сохранение группы в виде фикстуры либо реализована специальная команда для заполнения групп с
      настроенными правами в БД — для передачи на проверку наставнику.

**Реализация механизма владения продуктами:**

- в модель `Product` добавлено поле `owner`, связанное с моделью пользователя через `ForeignKey`;

    - настроена автоматическая привязка продукта к авторизованному пользователю при создании:

        - при создании нового продукта поле `owner` автоматически заполняется идентификатором текущего авторизованного
          пользователя;

    - реализованы проверки прав доступа в представлениях (views):

        - редактировать и удалять продукт может только его владелец;

        - дополнительно при запросе удаления проверяется наличие у пользователя группы «Модератор продуктов» —
          модераторы также имеют право удалять продукты независимо от владения;

    - обновлены шаблоны отображения продуктов:

        - кнопки редактирования и удаления отображаются исключительно для владельца продукта;

        - интерфейс адаптирован с учётом ролей пользователей: видимость элементов управления (редактирование, удаление,
          отмена публикации) зависит от прав и роли текущего пользователя.

## 📦 Список зависимостей и установка

Для корректной работы проекта необходимы следующие зависимости:

### 1. Установка PostgreSQL

PostgreSQL — система управления реляционными базами данных, используемая в данном проекте.

- Скачать и установить PostgreSQL можно отсюда: [PostgreSQL Download Page](https://www.postgresql.org/download/)

### 2. Необходимые Python-пакеты

Установите следующие библиотеки:

- **psycopg2** — драйвер для работы с PostgreSQL:

```bash
pip install psycopg2
```

- **python-dotenv** — библиотека для загрузки переменных окружения из `.env` файла:

```bash
pip install python-dotenv
```

- **Pillow** — библиотека для работы с изображениями:

```bash
pip install pillow
```

- **IPython** — интерактивная оболочка для Django shell:

```bash
pip install ipython
```

### 3. Работа с Django shell

Для запуска Django shell с поддержкой IPython воспользуйтесь следующей командой:

```bash
python manage.py shell -i ipython
```
